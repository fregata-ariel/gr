### 記録 → 検証(EOS NLL の上昇、短距離 REF の悪化)

予測時点の階層内カウント(lpos)で層別:

| lpos | EOS baseline → 案 1 | REF_2/3 baseline → 案 1 | top-level KIND |
|---|---|---|---|
| 0–3 | 0.08 → 0.17 | 0.76 → 0.93 | 0.71 → 0.71 |
| 4–7 | 0.08 → 0.29 | 0.77 → 0.93 | 0.80 → 0.85 |

| 12+ | 0.16 → **0.50** | 0.69 → 0.98 | 0.73 → 0.82 |

学習曲線: best 時点の train loss は同等(0.665 vs 0.667)だが val は高い
(0.762 vs 0.725)。最終は train 0.598 / val 0.786(baseline 0.633 / 0.739)。

判断: EOS の悪化はカウント値が大きいほど拡大し(希少値の学習型埋め込みが
未学習)、短距離 REF は全帯で一様に悪化。**絶対カウント値の学習型埋め込みが
「正確なカウントをキーにした暗記」を助長し汎化を損なう**と解釈する。
生成側(カウント失敗の消滅)は本物の改善であり、表現の方向は正しいが
パラメータ化が問題。

### 次: 案 1′(固定の正弦波エンコーディング)

lpos 埋め込みを学習型から固定正弦波(滑らか、未見のカウント値へも汎化)に
置き換える `--struct-pos-mode sinusoidal`。深さは値域が小さいので学習型のまま。
判定基準: WF の改善を保ちつつ val NLL・EOS NLL が baseline 水準へ戻ること。
戻らなければ案 2(pointer 型参照ヘッド)へ。

## 案 2(実装済み `d105a92`): pointer 型参照ヘッド

### 動機

案 1 は「距離 k を数える」負担を明示カウンタで軽減したが、参照はなお
`REF_k` という**距離トークンの分類**であり、(a) 語彙に REF 窓の上限がある、
(b) 距離が大きいほどクラスが希薄で学習しにくい、(c) 絶対カウント値への依存が
暗記を招く、という構造的制約が残る。pointer 型は「どの Motif を参照するか」を
同一階層の過去 Motif への注意で直接選ぶため、距離は副産物になり (a)〜(c) が
同時に消える。

### 仕様(案)

- **トークン列は不変**(canonical schema・`detokenize`・評価軸はそのまま)。
  変わるのは REF トークンの**予測方法**のみ。
- 各位置で 2 段の予測: (1) 通常ヘッドで「次は KIND / LOOP_* / EOS / REF のどれか」
  (REF はまとめて 1 クラス `REF`)、(2) 次が REF なら pointer ヘッドが
  「同一階層の過去 KIND トークン位置」上の分布を出す(query = 現在の隠れ状態、
  key = 各候補 KIND トークンの隠れ状態)。距離 k は選ばれた候補の階層内位置から
  決定的に復元し、`REF_k` トークンとして系列に戻す。
- 候補集合(同一階層・現在 Motif より前・既参照より遠い)は `GrammarState` /
  `structural_positions` から機械的に得られる → 学習時は mask 付き softmax、
  生成時は制約デコードと自然に一体化する(不正な候補は最初から存在しない)。
- 損失 = 種別ヘッドの CE + (REF 位置のみ)pointer の CE。teacher-forced の
  per-token NLL は「種別 NLL + pointer NLL」として同じ trace 形式で出力し、
  **REF NLL-by-k 曲線をそのまま比較可能**にする。

### 判定基準

- 主軸: REF NLL-by-k 曲線が k に対して平坦化(k=1 と k=8 の差が縮む)、
  `mean_offset` の ρ が低下、非制約 WF が案 1 水準以上。
- canary: `max_in_degree`(複数参照を持つ merge で候補が競合しやすい)を
  最重点で監視。EOS / LOOP NLL は baseline 水準に戻ること。

### 記録 → 検証(短中距離 REF の悪化、`ref_not_increasing` 多発)

REF NLL を「距離 k × 合法候補数(lpos−1−klast)」で層別(baseline → 案 2):

| k | 候補 1–2 | 3–5 | 6–9 | 10+ |
|---|---|---|---|---|
| 1 | 0.14→0.10 | 0.37→0.29 | 0.38→0.36 | 0.33→0.34 |
| 2–3 | 0.54→**0.73** | 0.82→1.05 | 0.87→1.16 | 0.80→1.10 |
| 4–6 | 1.96→2.22 | 2.29→2.35 | 2.48→2.88 | 2.42→3.04 |
| 7+ | 4.23→3.37 | 4.76→3.73 | 5.10→4.58 | 4.47→4.34 |

- k=1 は全帯で同等以上 → 「近さのバイアス欠如」は主因ではない。
- k=2–3 は**合法候補が 1–2 個でも悪化**(n=521)。候補宇宙に含めた
  既参照・近すぎる候補(k ≤ klast)へ確率質量が漏れている = 単調性の除外を
  学習しきれていない。生成側の `ref_not_increasing` 178 件と同根。
- k≥7 は一貫して改善: 長距離参照を注意で選ぶ利点は本物。

### 次: 案 2′(合法候補上の pointer + 距離バイアス)

1. 候補宇宙を文法的に合法な集合(k > klast、語彙窓内)に限定して学習・生成
   (`--pointer-legal`)。pointer は構造化出力であり、合法集合上の softmax が自然。
   非制約診断では `ref_not_increasing` が構成的に消えるため、診断の意味は
   「type 判断(REF を出すか・閉じるか)」に絞られる。
2. スコアに学習型の距離バイアス b[k] を加算(`--pointer-dist-bias`)。
   k=2–3 の識別を補助する安価な事前分布。
判定基準は案 2 と同じ(REF NLL-by-k の平坦化と全体 NLL の回復、WF ≥ 案 1)。

### 案 2″(文脈条件付き距離ロジット + 合法候補ゼロ時の REF マスク)— 実装 `ab75da6`, `0b18211`
