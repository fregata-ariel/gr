## 案 1: 階層内カウント・深さの学習型埋め込み(`--struct-pos`)

実装: `grammar_mask.structural_positions()` が各トークン消費後の
(深さ, 階層内 Motif 数)を与え、`train_ar.py` がそれぞれ学習型埋め込みとして
トークン埋め込みに加算する(`03577c2`)。

### 記録 → 検証(EOS NLL の上昇、短距離 REF の悪化)

予測時点の階層内カウント(lpos)で層別:

| lpos | EOS baseline → 案 1 | REF_2/3 baseline → 案 1 | top-level KIND |
|---|---|---|---|
| 0–3 | 0.08 → 0.17 | 0.76 → 0.93 | 0.71 → 0.71 |
| 4–7 | 0.08 → 0.29 | 0.77 → 0.93 | 0.80 → 0.85 |
| 8–11 | 0.15 → 0.34 | 0.83 → 1.01 | 0.82 → 0.89 |
| 12+ | 0.16 → **0.50** | 0.69 → 0.98 | 0.73 → 0.82 |

学習曲線: best 時点の train loss は同等(0.665 vs 0.667)だが val は高い
(0.762 vs 0.725)。最終は train 0.598 / val 0.786(baseline 0.633 / 0.739)。

判断: EOS の悪化はカウント値が大きいほど拡大し(希少値の学習型埋め込みが
未学習)、短距離 REF は全帯で一様に悪化。**絶対カウント値の学習型埋め込みが
「正確なカウントをキーにした暗記」を助長し汎化を損なう**と解釈する。
生成側(カウント失敗の消滅)は本物の改善であり、表現の方向は正しいが
パラメータ化が問題。

### n32 結果(sp_n32 vs sweep_n32)— n24 の傾向を再現

| 軸 | baseline | 案 1 |
|---|---|---|
| 非制約 WF | 53.5% | **86.2%** |
| `ref_out_of_range` / `unbalanced_loop_end` | 146 / 23 | **23** / 2 |
| `ref_not_increasing` / `loop_start_misplaced` | 4 / 3 | 17 / 7 |
| val NLL/token | 0.772 | 0.790 |
| REF NLL k=3 / k=4 | 1.22 / 2.11 | 1.34 / 2.25 |
| REF NLL k=7 / k=9 / k=10 | 4.09 / 5.39 / 4.69 | 3.66 / 4.44 / 3.71 |
| best epoch(train loss at best) | 82(0.712) | 46(0.713) |
| canary C: EOS NLL / LOOP NLL | 0.24 / 0.77 | **0.57** / **0.89**(両方フラグ) |

検証(lpos 層別): EOS は全帯で悪化(4–7: 0.21→0.48、8–11: 0.25→0.68、
12+: 0.23→0.46)で n24 ほど単調ではない。短距離 REF はほぼ同等。
LOOP_* の NLL も上昇(新規フラグ)。

解釈の更新: 悪化は「希少カウント値」だけでは説明できず、**構造を閉じる判断
(EOS / LOOP_END)が絶対カウント値をキーに暗記されて汎化しない**ことが主因と
みる(同じ train loss で val が高い、final の過学習も速い)。長距離 REF の改善
(k≥5)と生成時カウント失敗の消滅は両点で再現しており、方向性は確定。

### 次: 案 1′(固定の正弦波エンコーディング)

lpos 埋め込みを学習型から固定正弦波(滑らか、未見のカウント値へも汎化)に
置き換える `--struct-pos-mode sinusoidal`。深さは値域が小さいので学習型のまま。
判定基準: WF の改善を保ちつつ val NLL・EOS NLL が baseline 水準へ戻ること。
戻らなければ案 2(pointer 型参照ヘッド)へ。
